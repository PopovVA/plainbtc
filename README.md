# PlainBTC

Plain-English Bitcoin & crypto news for beginners.

**Live site:** [https://plainbtc.com](https://plainbtc.com)

Static HTML site (no bundler; `tools/build_i18n.py` generates the pages). Deployed by Cloudflare Pages from this repository.

```bash
python3 tools/build_i18n.py --check   # validate translations
python3 tools/build_i18n.py           # build every page, feeds, sitemap, llms.txt, hashed CSS/JS
python3 tools/check_site.py           # SEO tags, JSON-LD, links, images, sitemap, feeds (exits 1 on problems)
python3 tools/dev_server.py           # local preview on http://localhost:8788 with Cloudflare-style pretty URLs
```

## Design system ("signal, not noise")

One idea runs through the site: noise on the left resolves into one plain orange line (the logo mark, the hero graphic, the reading-progress bar, the footer rule).

* **Styles**: edit `assets/styles.css`. Tokens at the top (`--paper`, `--ink`, `--accent`, ...) define the light theme; the dark theme overrides them under `prefers-color-scheme: dark` and `:root[data-theme="dark"]`.
* **Script**: edit `assets/site.js` (analytics beacon, newsletter form, click tracking, then the interface code: theme switch, hero animation, scroll reveals, reading progress, table of contents, copy link, mobile newsletter bar). No dependencies. Everything is an enhancement: pages work without JavaScript, and `prefers-reduced-motion` switches the motion off.
* **Cache busting is automatic**: the build copies both files to `assets/styles.<hash>.css` / `assets/site.<hash>.js`, points every page at the copies and deletes the stale ones. Never link the hashed names by hand.
* **Fonts**: Source Serif 4 (SIL Open Font License) is self-hosted in `assets/fonts/`; labels use the system monospace stack; Japanese and Korean use system fonts. No third-party requests.
* **Shared markup** lives in `tools/build_i18n.py`: `assets_block()` (head), `site_header_html()`, `site_footer_html()`, `home_main()`, `article_head_html()`, `card_html()`. The build writes the same markup into the hand-written English pages, so a design change is made once.

Includes market recaps, beginner guides, regulation notes, sitemap, RSS (`feed.xml`), `/llms.txt` (all articles in all languages, generated by `tools/build_i18n.py`), and FTC affiliate disclosure pages.

Referral CTAs use `rel="sponsored"`. Nothing on the site is financial advice.


## Open Graph images

Article and page link previews (X / Facebook / Slack) use 1200×630 PNGs in `assets/og/`.

Generate or refresh an image:

```bash
python3 tools/make_og.py <slug> "<Headline title>" "<LABEL>"
# examples:
python3 tools/make_og.py my-new-article "Why bitcoin moved today" "MARKET NEWS"
python3 tools/make_og.py --all   # rebuild every known article + default.png
```

Then point the article's `og:image` / `twitter:image` meta tags (and NewsArticle JSON-LD `image`) at:

`https://plainbtc.com/assets/og/<slug>.png`

Labels that look good: `MARKET NEWS`, `REGULATION`, `GUIDE`, `BUSINESS`, `PLAINBTC`.
Requires Python 3 + Pillow (`pip install Pillow`) and DejaVu fonts.




## Mid-article images

Every news/guide article should show the hero/OG image at the top **and two more images in the middle of the body** (after ~paragraph 2–3 and again around the mid-CTA). Prefer:

1. A **chart** from real public data (CoinGecko price series, or bar charts of figures cited in the article’s sources).
2. A **fact card** highlighting one key number/quote from those sources (Pillow, same navy/orange brand as OG images).

Generate both with:

```bash
# needs: python3 -m venv .venv && .venv/bin/pip install matplotlib Pillow
.venv/bin/python tools/make_article_images.py --all
.venv/bin/python tools/make_article_images.py <slug>
```

Outputs land in `assets/img/<slug>/` (webp preferred, &lt;200 KB) and `i18n/content/<slug>/figures.json` (per-language `alt` + `caption`).

In every language body (`i18n/content/<slug>/<lang>.txt`) insert markers in the **same places**:

```
!figure:chart
!figure:fact
```

`tools/build_i18n.py` turns those into `<figure class="article-figure">…</figure>` blocks. English HTML under `articles/` is still hand-edited: paste the same two figures (see an existing article for the markup) and keep the hero `<img class="og-hero">`.

Never invent chart numbers. Never hotlink news-outlet photos — only official press-kit assets with credit, or graphics you generate.

## Homepage article cards (thumbnails)

Every home page (`/` and `/<lang>/`) lists articles as cards. Each card shows a **topical 16:9 thumbnail** at the top (clickable to the article). Prefer a subject-specific image — not the OG title card:

1. `assets/img/<slug>/thumb.webp` (640×360) generated by `tools/make_card_thumbs.py` from Wikimedia / U.S. government public-domain photos, official logos for identification, or charts from real market data (Kraken OHLC). Credits: `assets/img/<slug>/thumb.credits.json`.
2. Else `thumb.jpg` in the same folder.
3. Else fall back to `/assets/og/<slug>.png`.

```bash
.venv/bin/python tools/make_card_thumbs.py --all
.venv/bin/python tools/make_card_thumbs.py <slug>
```

* Non-English homes are generated by `tools/build_i18n.py` (`article_cards()` / `card_thumb_src()`).
* The English home (`index.html`) is patched on every build between `<!-- i18n:articles -->` markers with the same cards.

Card markup shape (for reference; `card_html()` in the builder writes it):

```html
<article class="card" data-kind="news|guide">
  <a class="card-thumb" href="/articles/<slug>" tabindex="-1" aria-hidden="true">
    <img src="/assets/img/<slug>/thumb.webp" width="640" height="360" alt="…" loading="lazy" decoding="async">
  </a>
  <div class="card-body">
    <div class="meta">Label · Date · ~N min</div>
    <h3><a href="/articles/<slug>">Title</a></h3>
    <p>Summary</p>
    <a class="read-more" href="/articles/<slug>">Read article →</a>
  </div>
</article>
```

The first card is the lead story (`card-lead`, full width). **The order of the cards between the `<!-- i18n:articles -->` markers in `index.html` is the order of the whole site** (home pages, ticker, feeds, llms.txt): to publish a new article, put its card first in that block (a minimal `<article class="card">` with the title link, `.meta` and summary `<p>` is enough; the build rewrites it). Guides (`"disclosure_variant": "guide"` or `"kind": "guide"` in `meta.json`) are also listed in the "Beginner guides" index on the home page.

Do **not** bake the article title into the thumb (the card already shows it). Styles live in `assets/styles.css`.

## Multilingual site (10 languages)

Languages (see `i18n/langs.json`): `en` (default, no URL prefix — existing URLs never change), `es`, `pt` (Brazilian, hreflang `pt-BR`), `fr`, `de`, `ru`, `tr`, `id`, `ja`, `ko`.

URL scheme: `/` and `/articles/<slug>` stay English. Every other language lives under its prefix:
`/<lang>/` (home), `/<lang>/articles/<slug>`, `/<lang>/about`, `/<lang>/disclosure`, `/<lang>/feed.xml`.
Every page carries `hreflang` alternates for all 10 languages + `x-default` (= English), a self-referencing canonical, localized `<html lang>`, title/description/OG tags/`og:locale`, JSON-LD `inLanguage`, and a language switcher (header menu + footer list). OG images are reused from the English article. `sitemap.xml` is a single sitemap with `xhtml:link` alternates and an `image:image` entry per article (page URLs only; feeds are discovered through `<link rel="alternate">`).

### What is generated vs hand-written

* English articles/pages are still hand-written HTML (`articles/<slug>.html`, `index.html`, `about.html`, `disclosure.html`, `404.html`). `tools/build_i18n.py` *patches* them in place and is safe to re-run. It rewrites the head assets block (`<!-- i18n:assets -->`), the site header and footer, the hreflang block, and:
  * on the home page the whole `<main>` (ticker, hero, stats, cards, guides index, newsletter, community) and its JSON-LD. Only three things are read back from `index.html` and kept: the hero `<h1>` text, the hero lead paragraph, and the "About this site" box. Edit those in place.
  * on articles the head block between `<!-- i18n:arthead -->` markers (breadcrumbs, label, `<h1>`, byline, share row, hero image). The label, headline and byline text are read back from the page, so edit them in place. A new article may still start with the old short form (`<a class="back">`, `.badge`, `<h1>`, `.meta`, `<img class="og-hero">`); the build converts it. The article body is not touched, except for the community / newsletter / related / partner blocks described below.
  * article JSON-LD: publisher logo, `Article` for guides and `NewsArticle` for news, `articleSection`, and the precise publication time kept in `feed.xml`.
  * relative `*.html` links, which become the canonical pretty URLs (`/about`, `/articles/<slug>`).
* Everything under `es/ pt/ fr/ de/ ru/ tr/ id/ ja/ ko/` and `sitemap.xml` is **generated — do not edit by hand**. Edit the sources under `i18n/` and rebuild.

### Workflow for every new English article

```bash
# 1. After the English article HTML is written (with title, description, OG, JSON-LD, sources, related):
#    OG preview image + topical homepage card thumb (distinct from OG title card):
python3 tools/make_og.py <slug> "<Headline title>" "<LABEL>"
.venv/bin/python tools/make_card_thumbs.py <slug>
python3 tools/i18n_extract.py <slug>
#    -> i18n/content/<slug>/{meta.json, links.json, en.txt}
#    (use --all to re-extract everything; then re-apply manual edits to en.txt, e.g. the {{#ref}} sentence in the how-to)

# 2. Write 9 translations: i18n/content/<slug>/{es,pt,fr,de,ru,tr,id,ja,ko}.txt
#    Same block sequence as en.txt, natural native wording, facts/numbers/sources unchanged.

# 3. Validate and build (home cards use assets/img/<slug>/thumb.webp when present, else OG)
python3 tools/build_i18n.py --check     # block order, link keys, lists, numbers, inline tags, {{#ref}} markers
python3 tools/build_i18n.py             # writes <lang>/..., feeds, sitemap.xml; patches English pages + article cards

# 4. Commit, push, then ping search engines
python3 tools/indexnow.py
```

An article without a translation simply has no alternates and is skipped on non-English index pages (it is still in the sitemap as English).
Also remember: new articles should be added to `related` in `meta.json` of other articles only if you want cross-links; the English "related" list is extracted from the HTML.

### Translation file format (`i18n/content/<slug>/<lang>.txt`)

```
title: ...            # <h1>
page_title: ...       # <title> prefix (site name added by the builder)
description: ...      # meta description
og_description: ...
label: ...            # category label on cards
summary: ...          # card / home-page blurb
===
Paragraph blocks are separated by blank lines. Allowed inline HTML: <strong> <em> <code> <br>.
Links: [text](L1)  -> URL from links.json key L1;   [text](REF) -> Coinbase referral link (English/`full` only; plain text in other languages)
{{#ref}} through our referral link{{/ref}}   -> only shown in languages with referral mode `full` (currently English only)
## Heading
!takeaways
- bullet
- bullet
!mid_cta            # mid-article Coinbase banner (rendered only in `full` / `hedged`; currently English only)
!soft: Text with [link](/articles/other-slug).   # soft internal-link CTA
!end_cta            # end-of-article CTA: Coinbase referral in `full`/`hedged`; non-affiliate closer in `none`
!disclosure         # standard disclosure box for this article's disclosure_variant
```
The block sequence (headings, paragraphs, lists, `!` blocks), link keys and numbers must match `en.txt`; `--check` reports mismatches (a few benign warnings, e.g. `ja`/`ko` number grouping, are expected).

### UI strings, static pages

* `i18n/strings/<lang>.json` — navigation, footer, labels, banner/CTA/disclosure text, home hero, month names.
* `i18n/pages/<lang>/{about,disclosure}.txt` — about and disclosure pages (same format).

### Coinbase referral per language (`referral` in `i18n/langs.json`)

Policy (9 November 2026): the Coinbase referral (`https://coinbase.com/join/F2XRWRL?src=referral-link`, inline `[text](REF)` links, mid-article banner, end CTA, and per-article affiliate disclosure) appears **only on English pages** (the site root, no language prefix). The URL itself lives in `i18n/partners.json` (`id: coinbase`).

* `full` (en only): inline referral link, mid-article banner, end CTA, and affiliate disclosure. CTA and disclosure wording must stay accurate to Coinbase’s official invite terms: the offer is for new U.S. customers and is not available in Washington state; point readers to Coinbase’s site for current terms. Do not state bonus amounts.
* `hedged` / `soft`: still supported by the builder for a future local referral, but **not used**. Do not turn these on for Coinbase.
* `none` (es, pt, fr, de, ru, tr, id, ja, ko): no Coinbase referral URL, no Coinbase banner, no Coinbase affiliate disclosure line. Inline `[text](REF)` and `{{#ref}}…{{/ref}}` render as plain text (or are omitted). The end-of-article `!end_cta` becomes a non-affiliate box (`alt_cta_title` / `alt_cta_text` in `i18n/strings/<lang>.json`) pointing to the newsletter, community, and related guides — unless another partner is live for that language (see below). Neutral mentions of Coinbase as a company in news copy are fine.

Disclosure pages must stay accurate: English pages may contain Coinbase and/or Gemini referral links; Spanish and Portuguese pages may contain an Uphold referral link; other language editions have no referral links. Never put `coinbase.com/join` or the Coinbase referral code on a non-English page (including disclosure and newsletter templates). Change a language’s mode in `langs.json` and rebuild to adjust the Coinbase policy. Never invent bonus amounts in any language except where official program terms require disclosing a specific figure — then quote the official number and date.

### Other referral partners (`i18n/partners.json`)

Additional partners (River, Gemini, Uphold, and reserved slots for Public and SoFi) are configured in `i18n/partners.json`. **Live as of 9 November 2026:**

* `en` — Coinbase, Gemini, and River. Public personal referrals are forbidden for the blog; SoFi is affiliate-only (Impact).
* `es`, `pt` — Uphold only. Gemini is **not** enabled here: official Gemini pages state that effective 6 April 2026 Gemini closed all customer accounts in the UK, the EEA, and Australia.
* `fr`, `de`, `ru`, `tr`, `id`, `ja`, `ko` — none.

**CTA rotation:** each article’s mid-article banner and end CTA feature **one** primary partner, chosen deterministically from the partners live for that language (hash of `slug|lang`, plus topic hints). Bitcoin-only / savings / DCA topics prefer River when River is live; general exchange / altcoin topics prefer Gemini or Coinbase. The Coinbase beginner / product guides (`how-to-buy-first-bitcoin-coinbase`, `coinbase-fees-explained`, `how-to-cash-out-bitcoin-coinbase-to-bank`, `is-coinbase-safe-for-beginners`) stay on Coinbase. An article can pin a partner with `primary_partner` in `meta.json` (`"none"` suppresses the referral CTA). The build prints the per-language distribution. Click tracking records which partner was clicked (`data-partner` on every referral anchor).

Do not add Gemini to `es`/`pt`/`fr`/`de` unless Gemini officially reopens those markets.

A partner is **live on the site only when all of the following are true**:

1. `enabled` is `true`
2. `url` is a non-empty `https://` link (no placeholder URLs)
3. `share_policy` allows it: `allowed` can go live; `forbidden` is rejected by the builder even if a URL is pasted; `affiliate_only` requires `url_type` to be `"affiliate"` (an approved affiliate link, not a personal referral link)

Until then the slot stays dark: the builder emits no HTML, no links, and no new disclosure lines. CTA copy and per-language disclosure text can be prepared in the JSON in advance.

**How to activate a partner once the referral or affiliate URL arrives:**

1. Confirm official terms still allow posting the link on a blog (re-read `share_policy` and the program’s current terms). Do not activate `public` (commercial use is forbidden) or a personal SoFi referral (`sofi` is `affiliate_only`).
2. In `i18n/partners.json`, paste the real `https://` URL into that partner’s `url` field and set `enabled` to `true`. For SoFi, also set `url_type` to `"affiliate"`.
3. Keep CTA/disclosure wording hedged and accurate. Do not invent or state bonus amounts (except where a program’s official rules require disclosing the specific compensation — then quote the current official figure and date, and point to the official terms).
4. On each language disclosure page that will now carry the link (`i18n/pages/<lang>/disclosure.txt`), insert a `!partners` block in the referral section and rewrite any sentence that said this language edition has **no** referral links. English `disclosure.html` is patched automatically when extra English partners go live.
5. Run `python3 tools/build_i18n.py --check` then `python3 tools/build_i18n.py`. The article end CTA shows the single primary partner for that article and language. Community and newsletter blocks are unchanged. The build prints the CTA distribution.
6. Commit, push, and spot-check the live pages (and `rel="sponsored"`).

To turn a partner off, clear `url` or set `enabled` to `false` and rebuild.

## Visit analytics (cookieless)

PlainBTC records pageviews with a tiny beacon in `assets/site.js` (served under a content-hashed name, `/assets/site.<hash>.js`) → Cloudflare Pages Function `POST /api/hit` (`functions/api/hit.js`) → Supabase table `public.pageviews`.

Referral clicks (Coinbase, Gemini, River, Uphold) are recorded the same way: a capture-phase click listener on `a[data-partner]` / `a[rel~=sponsored]` sends `navigator.sendBeacon` to `POST /api/click` (`functions/api/click.js`) → `public.referral_clicks` (`ts`, `partner`, `path`, `lang`, `referrer_host`, `utm_source`). No cookies, no IP. Schema and the `public.plainbtc_click_stats(date)` function are in `supabase/referral_clicks.sql`. Query one America/Chicago day with:

```sql
SELECT * FROM public.plainbtc_click_stats((timezone('America/Chicago', now()))::date);
```

`anon` may execute this aggregate function only (no table SELECT). For a Chicago-day report from the repo, use:

```bash
python3 tools/click_stats.py
python3 tools/click_stats.py --date 2026-11-09
```

It uses the same Supabase project and anon key as `POST /api/hit` and `tools/send_digest.py`, calls `plainbtc_click_stats`, and prints clicks per partner and per page. Default date is today in America/Chicago.

Privacy:
- No cookies, no `localStorage`, no raw IP stored.
- `visitor_hash` is a **daily salted** SHA-256 of IP+UA (America/Chicago day boundary) truncated to 16 hex chars — used only for a rough unique-visitor estimate.
- Country comes from the Cloudflare `CF-IPCountry` header inside the Pages Function.
- Obvious bots (`navigator.webdriver`, common bot UAs) are skipped client- and server-side.
- RLS: `anon` may **INSERT** only; no SELECT/UPDATE/DELETE via the Data API.

Data lives in the existing free Supabase project **foliata** (ref `ygilpnmqkduzhdkxdyxj`), table `public.pageviews`. (A dedicated project was blocked by the free-tier 2-project limit.)

### Query daily stats (America/Chicago)

In the Supabase SQL editor (service role / dashboard):

```sql
-- Yesterday (Chicago)
SELECT * FROM public.plainbtc_daily_stats(
  (timezone('America/Chicago', now())::date - 1)
);

-- A specific day
SELECT * FROM public.plainbtc_daily_stats('2026-11-09');

-- Raw recent hits
SELECT ts, path, lang, referrer_host, utm_source, country, device, visitor_hash
FROM public.pageviews
ORDER BY ts DESC
LIMIT 50;
```

`plainbtc_daily_stats` returns: `pageviews`, `uniques`, `top_paths`, `top_referrers`, `top_utm_sources`, `by_lang`, `by_country`, `by_device` (JSON arrays of `{k,c}`).


## UTM conventions for social / referral traffic

Tag outbound links to the site so morning reports can attribute channels:

| Channel   | Example |
|-----------|---------|
| X / Twitter | `https://plainbtc.com/articles/<slug>?utm_source=x&utm_medium=social&utm_campaign=<yyyy-mm-dd>` |
| Facebook group | `...?utm_source=facebook&utm_medium=social&utm_campaign=<yyyy-mm-dd>` |
| Reddit | `...?utm_source=reddit&utm_medium=social&utm_campaign=<yyyy-mm-dd>` |
| Discord | `...?utm_source=discord&utm_medium=social&utm_campaign=<yyyy-mm-dd>` |
| Coinbase referral landing mentions | keep the Coinbase join URL as-is; site CTAs already use the referral link |

Also accepted: `utm_medium=organic` / `email` / `bio`. Keep `utm_*` values lowercase, no spaces.


## Newsletter (email subscription)

* **Form**: one `<aside class="newsletter-box">` per page (home, every article, about, disclosure; all 10 languages), texts in `i18n/newsletter.json`. Injected by `tools/build_i18n.py` (`place_newsletter()`): strip-then-place between `<!-- i18n:newsletter -->` markers, so re-running the build always leaves exactly one form. New articles get it automatically via the normal workflow (`gen_en_article.py` → `build_i18n.py`). JS handler lives in `assets/site.js`; CSS in `assets/styles.css` (`.newsletter-box`, `.newsletter-form`). On the home page the form is part of `home_main()`. Honeypot field `website`.
* **Backend**: Pages Functions `POST /api/subscribe`, `GET /api/confirm?token=`, `GET|POST /api/unsubscribe?token=` (`functions/api/*.js`, helpers `functions/_lib/`; `nl_strings.js` is generated). They call SECURITY DEFINER RPCs in Supabase project foliata (`supabase/newsletter.sql`); tables `newsletter_subscribers` (email unique lowercased, lang, source, status pending/confirmed/unsubscribed, tokens, timestamps), `newsletter_signup_log`, `newsletter_state`, `newsletter_admin`, `newsletter_templates` have RLS on and no anon grants. No secret is needed in Cloudflare.
* **Double opt-in mail**: sent from inside Postgres (`pg_net`) through the Resend API with the key stored in Supabase Vault (`plainbtc_resend_key`); localized templates are rows in `newsletter_templates`. After editing `i18n/newsletter.json` run `python3 tools/newsletter_sync.py` and apply `supabase/newsletter_templates.sql` to the project.
* **Digest**: `python3 tools/send_digest.py --dry-run | --test-to ADDR | --send | --baseline | --stats` (see the docstring). Needs `RESEND_API_KEY` (or `/workspace/private/resend_api_key`) and `NEWSLETTER_ADMIN_TOKEN` (or `/workspace/private/plainbtc_newsletter_admin.token`; only its SHA-256 is in the database).
