라이터, 유출된 거래용 키로 공격자가 1,040만 달러 빼가자 출금 중단

게시일 2026년 11월 16일 · PlainBTC · 미국 · 약 5분 소요
공유

암호화폐 선물을 거래하는 탈중앙화 거래소 라이터(Lighter)가 월요일 오전 모든 출금을 중단했다. 공격자가 트레이더 한 명의 유출된 API 키를 이용해 스테이블코인 USDC로 약 1,040만 달러를 플랫폼에서 빼냈기 때문이라고 CoinDesk가 보도했다. 라이터는 자사 소프트웨어와 스마트 계약은 해킹되지 않았다고 밝혔다.

정오 무렵 거래소는 피해 트레이더를 위해 약 500만 달러를 회수했고 입출금을 다시 열었다고 밝혔다. CoinDesk에 따르면 라이터의 LIT 토큰은 소식이 전해진 뒤 10% 넘게 떨어져 2.48달러 아래로 내려갔다가 약 2.62달러로 회복했다.

핵심 요약

  • 11월 16일 월요일, 공격자가 트레이더 한 명의 유출된 API 키로 라이터에서 약 1,039만 USDC를 인출했다.
  • 라이터는 약 7시간 동안 출금과 신규 풀 생성을 중단했으며, 프로토콜과 스마트 계약은 영향을 받지 않았다고 밝혔다.
  • 키가 유출된 것은 트레이더가 직접 쓴 서명 코드가 일회용 숫자를 재사용했기 때문으로, 잘 알려진 암호학적 실수다.
  • 트레이더에게 약 500만 달러가 반환됐고, 출금은 미국 중부시간 오후 12시 21분쯤 재개됐다.

무슨 일이 있었나

API 키는 비밀번호와 비슷한 코드로, 계정 주인이 직접 클릭하지 않아도 거래 봇이 그 계정에서 주문을 낼 수 있게 해 준다. 블록체인 데이터 업체 Bitquery에 따르면 월요일 미국 중부시간 오전 4시 11분쯤 약 10,393,057 USDC가 라이터의 이더리움 계약에서 빠져나갔다. 돈을 받은 지갑은 약 4분 만에 이를 이더로 바꿨다.

한 시간도 지나지 않아 라이터는 X에 "단일한 외부 당사자가 침해된 것으로 보이는 보안 사고"를 조사 중이라고 올리고 모든 출금과 풀 생성을 중단했다. 중부시간 오전 6시 49분쯤 낸 후속 공지에서는 원인이 "특정 트레이더 계정의 API 키 유출"이라고 밝히고, 공격자의 것으로 보이는 지갑을 공개했다.

Cointelegraph에 따르면 분석 업체 버블맵스(Bubblemaps)도 같은 지갑을 추적했다. Bitquery는 이후 약 350만 달러어치인 1,920 ETH가 각각 160 ETH씩 12개의 새 지갑을 거쳐 하이퍼리퀴드(Hyperliquid) 거래소로 보내졌고, 각 지갑이 프라이버시 코인 모네로에서 이름을 딴 XMR1이라는 토큰을 샀다고 밝혔다. Bitquery가 마지막으로 확인했을 때 3,845 ETH는 여전히 주 지갑에 남아 있었다.

일부 연구자들은 마켓메이커 계정 두 곳에서 잠재 손실이 약 1,550만 달러에 이른다고 본다. 라이터는 이 더 큰 수치를 확인하지 않았다.

키는 어떻게 유출됐나

라이터는 월요일 정오 무렵 올린 상세 설명에서 피해 계정들이 자사 공식 소프트웨어 키트(SDK)를 쓰지 않았다고 밝혔다. 이 계정들의 자체 서명 코드는 디지털 서명마다 달라야 하는 무작위 일회용 숫자인 '논스(nonce)'를 재사용했다. 서명은 공개되기 때문에 같은 논스로 만든 서명 두 개만 있으면 누구나 비밀 키를 계산할 수 있다. 라이터는 같은 약점이 비트코인과 이더리움 서명에도 해당된다고 지적했다.

공격자는 이 키로 피해자 계정에서 공개 풀을 만들고, 다른 계정으로 풀 지분을 산 뒤, 피해자의 자금을 풀로 옮기고 자신의 지분을 현금화했다. 이상 거래가 감지되자 라이터의 비상 모드 '가디언(Guardian)'이 작동해 출금이 멈췄고, 거래소 보안위원회가 트레이더에게 약 500만 USDC를 돌려줄 수 있었다.

앞으로 달라지는 점

라이터는 이제 공개 풀로 자금을 옮기려면 지갑 서명이 필요하며, API 키 서명을 비공개로 바꿨다고 밝혔다. 또 키가 지정한 서버에서만 작동하도록 하는 IP 허용 목록과 키별 한도·권한 설정을 추가할 계획이다. 자신의 코드가 확실하지 않은 사용자에게는 모든 API 키를 교체하고 공식 키트로 바꾸라고 권고했다.

중부시간 오후 12시 21분쯤 라이터는 입출금이 "정상으로 돌아왔고" 대기 중인 출금을 처리하고 있다고 밝혔다. 트레이더의 나머지 손실을 보전할지는 밝히지 않았다.

초보자에게 주는 의미

대부분의 초보자는 API 키를 만들 일이 없지만, 이번 사건은 암호화폐 계정의 안전은 결국 키의 안전에 달려 있다는 점을 보여 준다. 거래 봇이나 세금 앱을 거래소에 연결한다면 키에는 꼭 필요한 최소 권한만 주고, 공유하는 코드에 절대 붙여 넣지 말며, 더 이상 쓰지 않는 키는 삭제하자. 많은 입문자는 직접 코드를 돌리는 대신 앱으로 사고파는 Coinbase 같은 대형 규제 거래소에서 시작하는 편을 택한다. 이 글은 투자 조언이 아니다.

앞으로 지켜볼 점

  • 라이터가 자금을 더 회수하거나 트레이더의 나머지 손실을 보전할지.
  • 약속한 IP 허용 목록과 키별 한도가 언제 도입될지.
  • 1,550만 달러라는 더 큰 손실 추정치가 확인될지.
