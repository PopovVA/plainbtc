Bitcoin Core fixes an AI-found bug that could stall nodes; about 40% of public nodes still run affected versions

Published Nov 22, 2026 · PlainBTC · United States · ~5 min
Share

The developers of Bitcoin Core, the most widely used software for running the Bitcoin network, disclosed a security bug on Friday, Nov. 20, that could make a node stop working for more than a dozen seconds at a time. The bug, listed as CVE-2026-117348, was first found by an artificial intelligence scan, according to the official advisory.

Fixes are in Bitcoin Core 30.5 and 31.3, released the same day, and in 32.1, released on Oct. 27. The older 29.x series has reached the end of its support and will not get a fix. The advisory rates the problem "medium" severity and describes a temporary stall. It does not describe any way to steal bitcoin or change anyone's balance.

Key takeaways

  • A peer could stall a Bitcoin Core node for over a dozen seconds per message by repeating one transaction ID up to 50,000 times.
  • Affected versions: 29.0 to 29.5, 30.0 to 30.4 and 31.0 to 31.2. Fixed: 30.5, 31.3 and 32.1. 29.x gets no fix.
  • An AI scan from Project Loupe at Spiral, Block's open-source bitcoin team, reported the bug in July.
  • On Sunday, about 40% of publicly reachable nodes still reported an affected Bitcoin Core version, PlainBTC found.

What a node is, and how the bug worked

A node is a computer that keeps its own copy of the Bitcoin blockchain, checks new payments and blocks, and passes them on to other nodes. Exchanges, miners, wallet services and many individual users run one.

Sometimes a node hears about a transaction before it has seen the earlier transaction that funded it. It holds this "orphan" and asks other nodes for the missing pieces. Since version 29.0, when a peer announces an orphan the node already holds, Bitcoin Core builds a list of the orphan's missing parents and checks each one, the advisory explains.

Nodes announce transactions in batches of up to 50,000 entries, and the software did not skip repeated entries. An attacker could first send an orphan with thousands of missing parents, then send batches repeating its ID 50,000 times. "Each such message stalls the node for over a dozen seconds, during which it processes no messages from other peers, including blocks," the advisory says. The fix makes a node handle each announced transaction only once per batch.

Why it matters

A stalled node is not a hacked wallet, but delays can hurt businesses. CoinDesk noted that an exchange relying on an affected node could be slow to credit deposits, and a miner could waste computing power working on an outdated view of the blockchain. Sending more messages could keep the node stuck longer.

The advisory calls the bug "easily discoverable." Under the security policy Bitcoin Core adopted on Oct. 22, CoinDesk reported, such bugs are fixed in all maintained versions as soon as possible and disclosed together with the releases, instead of waiting out the usual quiet period before disclosure. Developers worry that AI tools make this kind of flaw cheap to find again.

Found by AI, then by a human

The advisory credits an automated scan using a large language model, part of Elias Rohrer's Project Loupe at Spiral, Block's open-source bitcoin team. Loupe reported the issue on July 8. Bitcoin Core developer Gregory Sanders checked the finding and brought it to the security team. A second researcher, Stutxo, reported the same bug on Aug. 4, the day Sanders opened a fix. It was merged on Aug. 6, shipped in 32.1 on Oct. 27, and copied to the 30.x and 31.x versions released on Nov. 20.

How many nodes still need the update

PlainBTC grouped the 21,840 publicly reachable nodes in a BTC Nodes snapshot taken at 7:24 a.m. Central time on Sunday by the version they report. About 7,150 run a fixed Bitcoin Core release. About 6,140 run an affected 30.x or 31.x version that has an update available, and about 2,640 run 29.x, which will not get one. Together that is about 8,770 nodes, or roughly 40%.

These numbers are a rough guide. Nodes report their own version, the count covers only nodes that accept outside connections, and about 3,040 nodes run other or custom software that we did not count either way.

What it means for beginners

If you hold bitcoin on an exchange or in a phone wallet, you do not need to do anything. If you run your own node, for example on a home node box, check your Bitcoin Core version and update to 30.5, 31.3 or 32.1 (see the release notes). Users still on 29.x should move to a supported version. Only download Bitcoin Core from bitcoincore.org or your node software's official app store, since fake "urgent update" links are a common scam. If you are just starting out and buy through a large regulated exchange such as Coinbase, the exchange runs its own nodes, so there is nothing for you to update. This is not investment advice.

What to watch next

  • How quickly the share of nodes on affected versions falls over the coming weeks.
  • More AI-found bugs disclosed under Bitcoin Core's faster policy.
  • Updates from node software makers that bundle Bitcoin Core.
